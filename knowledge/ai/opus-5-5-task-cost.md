# Opus 5.5 で 1 タスクにかかる費用を見積もり、測る

トークン単価だけでなく、1 タスクが終わるまでの総額を左右する要因と、Opus 5.5 での設定の選び方をまとめる。
内容は claude.dev ブログ「What a task costs on Opus 5.5」（Addy Osmani 著、2026-09-25 公開）[^claude-article] の要約である。数値は記事の計算例や社内テストで、自分のタスクでの測定に置き換えて使う前提である。

## 費用を決める 4 要因

エージェントは毎ターン会話全体を再送するため、ターン数や思考量が多いモデルは、同じ単価でも高くつく。

1. ターン数: ターンごとに、それまでの会話を再送する。
1. キャッシュ読み取り: 再送分の大半は入力単価のごく一部で課金される。
1. 出力トークン: 思考を含み、入力の 5 倍の単価で最も高い。
1. モデル: モデルごとの単価。

記事の計算例は Opus 5.5 の API 定価（入力 $4/M、出力 $20/M、キャッシュ読み取り $0.20/M、キャッシュ書き込みは除外）を使う。

- 文脈が 20K から 120K へ 40 ターンで増えるタスク（平均 70K）は、入力が約 2.8M トークンになる。キャッシュ命中率 90% で約 $1.62、25 ターンなら約 $1.02。キャッシュなしなら $11.20、命中率 96% なら約 $0.99。
- 出力 60K トークンは $1.20 で、キャッシュ読み取り 6M トークンと同額になる。出力 1 トークンはキャッシュ読み取りの 100 倍である。

## Opus 5.5 での変化

- 価格: 入力と出力は Opus 5 より 20% 安く（$5 から $4、$25 から $20）、キャッシュ読み取りは 60% 安い（$0.50 から $0.20）。
- サブスクリプション: Pro、Max、Team の上限が約 25% 伸び、5 時間の上限も引き上げられた。対象者は上限のリセットも受けられる。
- 記事は、既定設定の典型的なトークン課金で Opus 5 より約 40% 安いと見積もる。トークン単価の 40% 引きではなく、価格と、既定が medium であることによるタスクあたりトークン減の合計である。
- 同じトークン量で比べると、キャッシュ読み取り 2.0M、新規入力 200K、出力 60K のセッションは $3.50 から $2.40 になり、約 31% 安い。
- 例の月額: 1 日 10 タスク、22 営業日、タスクあたり入力 2.2M（91% キャッシュ）と出力 60K で、Opus 5 は約 $770、Opus 5.5 は約 $528、差は約 $242（定価、割引なし）。
- 削減の幅は、キャッシュ主体のセッションで入力側が最大約 60%、出力が多い短いタスクで最大約 20%。大半はその間になる。
- 同じ effort では、Opus 5 より 1 ターンの思考が増える。特に xhigh と max で顕著である。

## effort の選び方

effort は low、medium、high、xhigh、max から選ぶ。Opus 5.5 の既定は medium（Opus 5 は high）である。

- 範囲が明確な日常作業は medium から始める。
- medium で行き詰まったら high に上げる。追加の思考 20K トークンは約 $0.40で、キャッシュ文脈 100K・出力 10K の 10 ターンの再試行ループと同程度である。
- 名前の置換や既知パターンの適用など機械的な作業は low にする。
- xhigh と max は、効果を測定できた作業に限る。
- 例: API のフィールド名変更で、medium はハンドラだけ直してクライアントを見落とし、high は呼び出し側まで読む。クライアントを通すテストがあれば、より安く検出できる。
- API キーまたは Claude サブスクリプションでは、途中で effort を変えてもキャッシュは残る。Bedrock、Google Cloud の Agent Platform、ゲートウェイではキャッシュが消える。

## モデル階層

- Haiku か Sonnet: 検索、要約するサブエージェント、ログやテスト出力の読み取り。コードの記述には向かない。
- Opus 5.5: 人が見ながら進める作業の標準。
- Fable 5.1: 最難関の作業、無人の長時間実行、コードベースに前例がない問題。入力 $10/M、出力 $50/M（Opus 5.5 の 2.5 倍）、キャッシュ読み取り $0.25/M（1.25 倍）である。目安は、Opus 5.5 の xhigh が同じ問題で 2 回失敗したら切り替え、解けたら戻す。切り替えは区切りで行い、最初のターンがキャッシュ書き込みを払うため、先に `/compact` する。
- サブエージェントのモデルは、定義の `model: haiku` や `model: sonnet`、または環境変数 `CLAUDE_CODE_SUBAGENT_MODEL` で指定する。定義の指定が環境変数より優先される。
- エージェントチームは plan モードで標準セッションの約 7 倍のトークンを使いうる。小さく保ち、終わったら止める。
- `opusplan`（Opus が計画し Sonnet が実行）は上の助言と逆の割り当てになるため、先に測る。

## プロンプトの見直し

移行後に `/claude-api prompt-audit` を実行すると、スキル、CLAUDE.md、アプリのコードにあるアンチパターンを指摘する。
記事の社内テスト（44 件のサポートチケット）では、Opus 4.8 から Opus 5.5 の low effort に移すだけで費用が約 18% 下がった。さらに、6 段階の手順、メモ欄の規則、二重確認の規則、矛盾する指示といった儀式的な指示を除くと、約 9% 下がり、開始時から約 25% 低くなった。1 つのベンチマークの結果である。

## キャッシュとセッションの扱い

- 読み取りは新規入力の 5%、書き込みは 1.25 倍（5 分）か 2 倍（1 時間）。
- 有効期間は、サブスクリプションで 1 時間、API キーとクラウドプロバイダーで 5 分（サブスクリプションでも利用クレジットを使い出すと 5 分）。ヒットのたびに時間がリセットされる。
- 文脈 120K では、5 分書き込みが約 $0.60、読み取りが約 $0.02。
- キャッシュが切れる原因は、有効期間を超える中断、モデルの切り替え、MCP の接続や切断、初回の fast mode、compact、ツール定義の変更（全消去）である。システムプロンプトの変更は、変更点以降が消える。
- 長い文脈は毎ターン高くなる。150K 文脈の 1 ターンのキャッシュ読み取りは約 $0.03で、20K なら約 $0.004。30 ターンで約 $0.90 と約 $0.12 になる。
- `/clear` は無料で、無関係な作業へ移るときに使う。`/compact` は 150K で約 $0.25 かかり、約 10 ターンで元が取れる。区切りでキャッシュが温かいうちに行う。長い中断の後だと約 $0.75 かかる。`/rewind` はキャッシュ済みの接頭辞に戻る。
- CLAUDE.md は毎回読み込まれるため、約 200 行以内に保つ。MCP のツール定義は遅延読み込みで、`/mcp` で接続中のサーバーを見直す。
- fast mode は約 2.5 倍速く、価格は 2 倍（$8/$40 per M）で、サブスクリプションでは利用クレジットに課金される。初回リクエストが未キャッシュの fast mode 入力価格を払うため、セッション開始時に有効にする。
- Batch API は入力と出力が半額。
- 目安として、コスト文書は企業の平均を 1 開発者・1 稼働日あたり約 $13、利用者の 90% が $30 未満と報告している。

## 測り方

1. タスク終了時に `/usage`（または `/cost`）を実行し、Session ブロックとキャッシュの行を見る。サブスクリプションの金額は定価ベースの推定で、請求額ではない。
1. 同じバックログのタスクを Opus 5 と Opus 5.5 で実行する（`claude update` で v2.1.280 以上にする）。ターン数、出力、費用を比べる。3、4 件で行う。
1. チームでは、Claude Code Analytics API でユーザー別の推定費用、Usage and Cost API でモデル別・キャッシュ別の支出を見る。
1. effort を試す。難しいタスクを medium と high で、機械的なタスクを low で実行する。

セッションの読み方は次のとおり。

- 長いのにキャッシュ割合が低い: 長い中断、モデル切り替え、後からの MCP 接続、クラウドでの effort 変更を疑う。
- 小さな変更なのに出力が多い: effort が高すぎるか、再試行している。
- 総入力が会話量の何倍にもなる: ループしている。

## 要点

- 範囲が明確な作業は medium で進め、モデルが自分の作業を検証できる手段を与える。
- effort 引き上げやモデル変更は、効果を測ってから行う。
- 検索用のサブエージェントは小さいモデルに、コード編集は Opus 5.5 に任せる。
- セッションを止めずにキャッシュを保ち、区切りで `/clear` と `/compact` を使う。
