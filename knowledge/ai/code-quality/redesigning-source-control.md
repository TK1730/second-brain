# Anthropic が自社のソース管理を作り直した理由

Anthropic が、エージェントによる大量のコード変更に耐えるため、モノレポを git から自社製の「Scion」へ移した話をまとめる。
内容は Anthropic のエンジニアリング記事（2026-10-13 公開、10-15 に Sapling の Mononoke に関する補足を追加）[^anthropic-article] の要約である。
性能の数値はすべて自己申告で、第三者の検証はない。

## 背景

- 記事は、コードを書くことはもはや制約ではなく、人の規模を前提にした開発基盤が制約だと述べる。
- マージは 2026 年 5 月の 1 日約 2,500 件から、9 月には 3 万件超になった。
- モノレポの main の履歴は約 100 GB、圧縮したワーキングコピーは 25 GB 超である。CI のチェックアウトは 1 日約 2,500 万回で、素朴に取得すると 1 日 600 PB 超の git の通信になると見積もっている。
- ピーク時には数百の社内 git ミラーを運用しており、マージ量の増加で運用が難しくなっていた。

## 発想

git は、全員が完全なコピーを持ち、オフラインでも作業できる分散型として設計された。Anthropic のクライアントは、ほぼすべてが常時接続のエージェントとジョブである。
そこで、常時接続を前提に一から設計したらどうなるか、を問い直した。5 か月でモノレポを移行し、同じ期間にコードレビュー（Antique）、コード検索、ソース管理用の IAM なども作った。

## 設計原則

- クライアントは常時接続: 必要なデータをその場で取得し、完全なコピーを持たない。
- サーバー主導: 履歴、blame、コミット、マージ、リベースはサーバーが行う。クライアントは上限つきのキャッシュと作業ファイルだけを持つ。
- プログラムから使える API: 自動の二分探索や巻き戻しのジョブが、ローカルのリポジトリなしで問い合わせられる。
- 水平に拡張できる: データを分散し、全体の複製はどこにもなく、パックファイルの保守が要らない。
- 軽くロックのないコミット: コミットはサーバーで行い、費用は変更の大きさに比例する。参照は main とリリースブランチ程度に抑える。
- ワーキングコピーは任意で疎: CI や書き込みの多くはチェックアウトなしで API から行い、仮想化したチェックアウトは読まれたファイルだけを取得する。

## 仕組み

- 変更セット: 作業の単位は、先行ログに書く変更セットである。木へのポインタではなく、最初の親との差分ファイルと、内容で指すブロブを持つ。
- 派生データ: blame、パスの履歴、コミットグラフの問い合わせは、変更セットから 1 つの汎用の仕組みで再帰的に計算する。先に計算しても後回しにしてもよい。内部をクライアントに見せないので、クライアントを更新せずに変えられる。
- 取得の手順: クライアントはルートの木から辿り、欲しい木とブロブだけを要求する。要求先は不変のオブジェクトなのでキャッシュでき、転送を再開でき、巨大なパックファイルが要らない。
- 階層キャッシュ: ノードごとのデーモン、地域のキャッシュ、権威サーバー（Spanner とクラウドストレージ）の 3 層で、障害を層ごとに分離する。

## 記事が報告する結果（自己申告）

- インフラの CPU とメモリは、従来の git ミラーより約 200 分の 1。
- CI と研究用のチェックアウトは分から秒へ、約 2 桁速い。CI だけで CPU 容量が約 25% 浮いた。
- 各キャッシュ層のヒット率は 99% 超。

## 教訓

- 7 人が 5 か月で Scion、Antique、ほかの 6 つほどのシステムを作った。この間、1 日のマージは 10 倍になった。
- 技術者は、コードを書く力では Claude が自分たちより上だと判断した。人の仕事は、制約を決め、エージェントが中核の不変条件を破ったら止め、変更の意図を見ることになった。敵対的なレビューは、守りすぎや作り込みすぎになることがあった。
- 初期の Claude が、手作りの取り込みの試作を書き直し、順序の不変条件を保ったままメモリ約 20 分の 1、速度約 4 倍にした。これは 1 例である。
- Claude は、隔離したシミュレーション、ファジング、レート制限を作り、祖先の問い合わせの最適化を見つけた。専門家なら数日から数週間かかる、と著者は述べる。
- 構成要素ごとに 1 つの Claude が、テレメトリとログを従来のアラートと並べて見守る。
- 従来の全体ロックのマージキューは、エージェント規模に合わない。マージ後とデプロイ前のテストに頼り、競合の解消は Claude のほうが人の検知より速いことが多い。

## 適用範囲と注意

- Scion は git の汎用の代替ではない。数万人のエンジニアや、エージェントの大量の出力を抱える巨大なモノレポ向けである。
- Anthropic の開発でのトークン支出は、一般の企業よりはるかに大きく、経済性は特殊である。
- 採用には、コードレビュー、検索、CI を含む開発の全工程の移行が必要で、これらは個別性が高い。製品としては提供しない。
- 狙いは考え方を共有し、git のプラットフォームがサーバー側の RPC や賢いプロトコルを取り入れて、git のモデルを保ったまま拡張できるようにすることである。
- 変更を最初の親との差分で持つのは、トランクベースの開発に合う選択である。Sapling の Mononoke の技術（Bonsai のデータモデルなど）に学んだと明記している。
- 性能、費用の比較、書き直しの逸話は社内の数値で、未検証である。
