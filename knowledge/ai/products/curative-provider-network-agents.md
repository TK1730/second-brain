# Curative の事例に学ぶ、契約業務を Claude エージェントに任せる設計

米国の雇用主向け医療保険を提供する Curative が、Claude 上のエージェントで全国の医療提供者ネットワークを築いている事例の要点をまとめる。
内容は Anthropic の記事（2026-11-10 公開、本文は英語）[^claude-article] の要約である。
顧客事例であり、数値の多くは Curative の自己申告か社内推計で、独立した検証はない。

## 背景

- Curative は、加入者が最初の受診を終えれば、ネットワーク内の医療を自己負担なしで受けられる保険を売っている。
- 全国のネットワークには大量の提供者契約が要る。2025 年の契約数は 2,100 件（前年の 2 倍）だったが、この速度では約 30 年かかるとされた。人の採用だけでは追いつかない、というのが出発点である。

## 作ったもの

| エージェント           | モデル | 役割                                                                                       |
| :--------------------- | :----- | :----------------------------------------------------------------------------------------- |
| Gwen（提供者契約）     | Opus   | 1 提供者を 1 回の実行で、アウトリーチから署名まで担当する。料率の提案、相手の修正案の方針照合、契約書の統合を行う |
| 料率レビュー           | Sonnet | 標準の料率を超える Gwen の要求を審査する。約 3 分の 2 を通し、残りは人（CEO）へ回す         |
| 判定役（ジャッジ）     | Haiku  | 送信前の全メッセージを読み、問題があれば理由を付けて差し戻す                               |
| 資格確認・データ登録   | -      | 署名後に提供者の免許を確認し、契約条件を登録して請求が正しく計算されるようにする           |
| Brad（営業）           | Opus   | ブローカー経由で雇用主へ販売し、見積の追跡や従業員データの抽出を行う。Gwen と違い記憶を持つ |
| 請求異議対応           | -      | メールや FAX の異議に、請求ごとの回答案を作る。人とエージェントの組で進める                |

- Gwen は問い合わせフォームからの受け身の案件と、こちらからの働きかけの両方を扱う。料率は購入した請求データと、保険者の公開価格ファイルをもとに調べる。
- 記事によれば、フォームから署名まで約 1 時間で進むことがある。
- エンジニア 13 人が Claude Code で、請求、事前承認、財務の各システムを今年作り直した。請求システムだけで 100 エンジニア年と見積もっていたとされる。

## 設計上の判断

- 汎用の道具を 1 つ持たせる。機能ごとに道具を分けた初期設計は、複雑な修正の取り込みで行き詰まった。文書ライブラリを使って Python を実行する 1 つの道具に替えて改善した。
- 相手の使う手段に合わせる。FAX 対応を足したところ、Gwen の成約率が 2 倍以上になったという。手書きで返す提供者が多いためである。基準となる数値は示されていない。
- 実行ごとに隔離する。Gwen は案件間の影響を避けるため、他の取引の記憶を持たない。一方、記憶を持つ Brad は、誤ったメモが残り続ける問題が起こりうる。
- 送信前に判定役を挟む。Gwen が内部の料率上限のメモを提供者に同報した出来事を受けて追加した。
- 権限は小さく始める。最初は標準料率を超える案をすべて人の承認待ちにし、段階的に緩めた。
- 保護対象の医療情報（PHI）は段階的に扱う。最初は PHI に触れない業務から始めた。扱う現在も、会話に入る情報を後方の制御で絞り、活動を監査用に記録する。HIPAA の業務提携契約（BAA）に依拠している。
- 人とエージェントの目標を揃える。契約担当者の報酬は、Gwen が主導した案件にも連動する。

## 人が確認する点

- 標準外や大規模グループの料率要求は CEO に回る。
- 送信前の判定役が全メッセージを確認する。
- 見込みの高い案件は、担当者が電話で引き継ぐ。
- 改善のため、数日ごとに直近約 1 万件の実行を Claude Code が抽出し、問題を拾って修正のプルリクエストを出す。
- Gwen が頼まれずにチラシを作る、会員が断られた診療所に受付の再教育を求めて確認する、といった自発的な行動が見られた。Curative は、自社のリスク許容度に照らして監視する対象とみなしている。

| 週あたりの新規契約         | 2,000 から 2,400 件                        | 自己申告               |
| 1 契約あたりのトークン     | 約 2,000 万。当初の約 10 分の 1 の費用     | 自己申告               |
| 契約チーム                 | 45 人から約 55 人。1 人あたり約 2.5 倍     | 自己申告               |

## 読むときの注意

- 成約率の上昇、費用の削減、「契約が約 50 倍速い」といった主張は、比較の基準が示されていない。
- 週あたり 2,000 から 2,400 件と、2025 年の年間 2,100 件が並んでおり、規模を解釈しにくい。
- 誤り率、規制当局の監査結果、会員への影響、トークン費用以外のコストは記事で扱われていない。
- 請求異議の処理は、正確性や不服申立ての扱いの説明が乏しい。

## 持ち帰れる実践

- 権限を小さく始め、段階的に広げる。
- 完全さではなく、人の誤り率との比較で評価する。
- 全ログ、送信前の判定役、実行の抽出レビューで、大量の動作を監査する。

記事は今後、会員支援の担当者 130 人向けのエージェントを計画していると述べる。
