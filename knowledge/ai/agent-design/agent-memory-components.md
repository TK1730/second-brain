# エージェントのメモリを層で設計し、dreaming で整理する

エージェントがセッションをまたいで経験を活かすためのメモリの構成と設計指針をまとめる。
内容は Anthropic Engineering の記事「The components of agent memory」（Lance Martin 氏、2026-11-06 公開）[^anthropic-article] の要約である。
数値は Anthropic 自身の評価によるもので、第三者の検証は記事にない。

## メモリの定義

- エージェントメモリは、利用者とのやり取りや課題から得た知識で、セッションをまたいで読める文脈として残るものを指す。
- 重みの更新、1 会話内の文脈内学習、コンパクション（古いターンを要約で置き換えること）は含めない。
- 人間の海馬が経験を素早く記録し、休息中に再生して長期記憶にするのになぞらえる。

## 4 つの層

| 層               | 内容                                                       |
| :--------------- | :--------------------------------------------------------- |
| トランスクリプト | エージェントの作業の、検索できるイベントログ               |
| メモリノート     | セッション中に Claude が書く、重要な観察（タグまたはファイル） |
| メモリ表現       | Claude が保守する、リンクされたページ群（wiki など）       |
| 注入コンテキスト | 新しいセッションの冒頭に毎回読み込む、小さな層             |

dreaming は、これらの層を行き来するオフラインの処理である。トランスクリプトでノートを訂正し、ノートから表現を作り、重要なものを上の層へ引き上げる。

## 設計の指針

- 方法ではなく目的を伝える。メモリが何のためにあるかを示すほうが、書き方を指示するより効く。
- 強いモデルには判断を任せる。「失敗だけ記録する」のような固定規則は、利得を下げた（Opus 5 で -0.234、Opus 4.7 で -0.150、Sonnet 4.6 で -0.020）。
- 弱いモデルにはより強く指示する。先にメモリを読み、仮説を確かめさせると大きく改善した。
- 注入コンテキストは小さく保つ。大きな指示ファイルは遵守を下げ、トークンを使う。詳細は下の層へ移し、リンクを残す。Claude Code の自動メモリは、`MEMORY.md` の先頭 200 行または 25 KB だけを読み込む。
- 環境から読み取れない情報だけを保存する。戦略、計画、検証済みの規則を残し、画面や状態から分かる事実は残さない。
- dreaming でノートをトランスクリプトと照合する。誤りやずれが次のセッションで信用されるのを防ぐ。
- 保守は変わりやすい情報に絞る。アクセス頻度などで周期を調整する。
- 並列のエージェントには、書き手ごとにページを与える。共有ファイルを上書きし合うとデータが失われる。
- dreaming の指示は課題に合わせる。契約条項など、重視する情報を明示する。
- トランスクリプト検索を土台にし、wiki は精度と肥大化を管理しながら重ねる。

## 評価結果

- CL-Bench のデータベース課題では、メモリありで平均報酬が上がった。Opus 5.5 は 0.655 から 0.838、Sonnet 5.5 は 0.644 から 0.833、Sonnet 4.6 は 0.330 から 0.364（プロンプトを改善して 0.641）だった。
- Pokémon Red では、Sonnet 3.7 が約 10,000 ステップで 413 ファイルを書いてバッジ 1 個、Fable 5 は約 9 ファイルと `global.md` でバッジ 4 個だった。メモリは多いほど良いとは限らない。
- 誤ったノートを dreaming で訂正した場合、エージェントは 1,935 手目で目的地に着いた。誤ったままのノートでは崖から 3 回落ち、メモリなしでは着けなかった。
- 約 35 万ファイルのコーパス（25 問）では、dreaming を 2 から 128 セッションに増やすと、wiki 単独の正答率が 13% から 48% に上がった。wiki と検索の併用は 54% から 61%（検索単独は 53%）で、1 問あたり約 2 万トークンを節約した。
- 契約条項の抽出では、複数のエージェントが共有の表に書くと 57 件中 41 件（72%）しか残らなかった。契約ごとに 1 エージェントで原文を引用すると 57 件すべてが残った。
- 複数文書や判断を要する問いでは、wiki と検索の併用が 87%、検索単独が 73% だった。単一文書の課題では明確な差がなかった。
- ある wiki は元の資料の 1.77 倍に膨らみ、リンクのないページもあった。

## 残る課題

- メモリの作成を、セッション中とオフラインのどちらで行うか。
- 環境の変化に合わせて、メモリをどう最新に保つか。
- メモリの保守と本来の作業に、計算量をどう配分するか。
