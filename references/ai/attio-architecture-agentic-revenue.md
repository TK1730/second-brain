# Attio のエージェント時代に向けた CRM アーキテクチャ

次世代 CRM プラットフォーム Attio のアーキテクチャ解説ページ「The architecture for agentic revenue」の要約である。
人間と自律型 AI エージェントが協働して収益業務 (Revenue Operations) を動かす時代に向け、アプリケーションの文脈管理とデータベースの規模・速度を融合したハイブリッド CRM アーキテクチャの設計思想と 5 つの主要コンポーネントを整理する。

## 概要: ハイブリッドアーキテクチャの次なるフェーズ (The next phase for hybrid architecture)

従来の CRM は、人間の担当者がブラウザ画面を開いてボタンをクリックし、1 件ずつレコードを操作する前提で設計されてきた。
そのため、AI エージェントが大量のデータに対して高速にクエリや推論を行おうとすると、API のレート制限や非効率なデータ構造がボトルネックになる。
Attio は、ビジネスアプリケーションが持つ豊かな文脈・柔軟なデータモデル・きめ細かな権限管理と、データインフラストラクチャが持つスケーラビリティ・低遅延のクエリ性能を統合した。
「エージェントから見ると、Attio はデータベースのように見える (To agents, Attio looks like a database)」という思想のもと、人間とエージェントの双方を第一級の利用者として扱う基盤を構築している。

## アーキテクチャを構成する 4 つの技術要素

概要とあわせて、Attio のアーキテクチャは以下の 4 つの技術要素 (全体で 5 つの柱) から構成される。

### 1. SQL Engine: エージェントの母国語としての SQL

- AI エージェントにとって最も自然で表現力の高い問い合わせ言語である SQL を、CRM のデータモデル上で直接実行できる組み込みの SQL エンジンを提供する。
- 複数オブジェクトをまたぐ `JOIN`、高度な集計 (`GROUP BY`)、ウィンドウ関数や数値計算を含む複雑なクエリをミリ秒単位で処理する。
- 出力は決定的で正確かつ監査可能 (Auditable) であり、LLM のハルシネーションを防ぎながら正確な顧客データの抽出・分析を行える。
- この SQL エンジンは、対話型アシスタントの Ask Attio、REST API、MCP (Model Context Protocol) サーバー、および自動化の Workflows から共通して呼び出すことができ、クエリ結果に基づいて即座にワークフローを起動できる。

### 2. Data Connectors: 同期不要のライブ直接接続

- ワークスペースのデータに対して、ライブの PostgreSQL 互換エンドポイントを提供する。
- Hex、Omni、Looker、Metabase、dbt などの BI・データ分析ツールや外部の自律エージェントから、標準的な PostgreSQL 認証情報を使って直接クエリを実行できる。
- 従来の CRM で一般的だった「夜間のバッチ ETL 同期」「データウェアハウスへの複製パイプラインの保守」「CSV エクスポート」が不要になり、常に最新の CRM データを単一の信頼できる情報源 (Single Source of Truth) として参照できる。
- 接続は読み取り専用 (Read-only) で安全に分離されており、ワークスペース管理者がいつでも認証情報のロール管理や即時失効を行える。

### 3. Agent Scale: 数千のエージェントが同時稼働するスケール

- 1 つのワークスペースあたり数億レコードの保持と、高スループットの読み書きワークロードに対応するよう設計されている。
- 人間のユーザーだけでなく、数千の自律エージェントがバックグラウンドで同時にデータの読み取り、推論、レコード更新やアクション実行を行っても、システム全体の性能劣化や「交通渋滞 (Traffic jams)」を起こさない。
- 高速な処理を維持しながらも、ワークスペースのロールベースアクセス制御 (RBAC) やフィールド単位の権限モデルがすべてのエージェント操作に対して厳密に適用される。

### 4. Activities: あらゆる顧客接点の第一級データ化

- 従来の CRM が扱ってきたメールやカレンダー予定だけでなく、カスタマーサポートの会話、SNS のダイレクトメッセージ (DM)、プロダクトの利用テレメトリ、エスカレーション履歴といった非従来型の顧客接点 (タッチポイント) をすべて取り込む。
- これらを単なるテキストメモやログとしてではなく、独自のスキーマ定義とリレーションを持つ「第一級の構造化データオブジェクト (First-class structured data objects)」としてモデル化・拡張できる。
- これにより、人間の担当者と AI エージェントの双方が、断片化のない 360 度の顧客コンテキストに基づいて判断・行動できる。

## まとめ: 5 つの柱の対応関係

| 柱 | 役割 | エージェント時代における利点 |
| :--- | :--- | :--- |
| Hybrid Architecture | アプリの文脈・権限と DB の速度の融合 | 人間の UI 操作とエージェントのプログラマティックな操作を同一基盤で両立する。 |
| SQL Engine | CRM 内での直接の SQL 実行 | Ask Attio、REST API、MCP、Workflows から正確で監査可能な集計・結合クエリを実行できる。 |
| Data Connectors | PostgreSQL 互換のライブ接続 | バッチ同期や CSV 出力をなくし、BI ツールや外部エージェントから直接ライブデータを参照できる。 |
| Agent Scale | 数億レコード・高並行スループット | 権限モデルを維持したまま、数千のエージェントが渋滞なく同時に読み書き・推論できる。 |
| Activities | 非従来型タッチポイントの構造化 | サポート会話やテレメトリを含む全接点をスキーマ付きオブジェクト化し、360 度の文脈を提供する。 |
