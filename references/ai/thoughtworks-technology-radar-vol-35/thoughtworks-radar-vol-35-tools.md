# Thoughtworks Technology Radar Vol.35: Tools

Thoughtworks Technology Radar Vol.35 (2026 年 11 月) の Tools (道具) 象限の要約である。
コーディングエージェントそのものと、それを支える道具 (課題管理、知識、レビュー、並列セッション管理、サンドボックス、セキュリティ) が中心である。
今号の Tools に Caution の項目は無い。

- 出典: Thoughtworks Technology Radar Volume 35 (PDF)、[thoughtworks.com/radar](https://www.thoughtworks.com/radar)

[TOC]

## Adopt

### 68. mise

- 道具と言語のバージョン管理、環境変数の管理、タスク実行の 3 つを、Rust 製の 1 つの道具と宣言的な `mise.toml` にまとめる。開発環境を揃える既定の選択肢として勧めている。
- Cosign や GitHub の成果物の証明と連携し、サプライチェーンの安全性も高める。言語ごとの既存の道具とも共存できる。

### 69. OpenAI Codex

- Claude Code、OpenCode と並び、日常的に使う CLI 型のコーディングエージェントとして Adopt に移った。デスクトップアプリはコードを書かない人にも人気がある。
- OS レベルのサンドボックス、段階的な承認、中央での設定管理を持つ。エージェントループは Apache-2.0 で、coding harness for general-purpose agents に使える。
- 他のエージェントの設定やスキルを取り込みやすく、OpenAI 以外のモデルも使えるため、オープンウェイトモデルを動かす選択肢にもなる。

### 70. OpenCode

- 代表的なオープンソースのコーディングエージェントハーネスである。カスタマイズ性とヘッドレス・サーバーモードがあり、enterprise harness の土台に向く。
- オープンウェイトモデルやローカルモデルと組み合わせる用途で人気がある。セッション共有や協働の機能は他より弱い。

## Trial

### 71. Act

- GitHub Actions のワークフローを手元で動かす。コーディングエージェントが push 前にワークフローを試せるので、CI をエージェントの生成ループに取り込める。
- 完全な再現ではない (一部の道具が既定のイメージに無い、並行実行や権限や環境のシークレットに非対応)。zizmor と組み合わせる。

### 72. Agent Package Manager

- プラグイン、スキル、指示、MCP サーバーをマニフェストで宣言する、エージェント設定の依存管理ツールである。中央のリポジトリからバージョン付きのスキルを配れる。
- エージェントのコンテキストをサプライチェーンとして扱う: 隠れた Unicode の検査、内容のハッシュと出所を持つロックファイル、SBOM の出力、ポリシーによる取得元の制限。まだ 1.0 前である。

### 73. ast-grep

- 構文木に対してパターンを当てる、構造的なコード検索・lint・書き換えの CLI である。ルールは YAML で書く。
- 索引も言語サーバーも要らず、大きなコードベースで手軽に始められる。独自ルールでエージェントのコードを調べ、結果をエージェントに返すハーネスとして使った例がある。

### 74. Beads

- コーディングエージェントが共有する、Git ベースの課題管理である。Markdown の計画の代わりに、構造化されたタスクの依存グラフを持たせる。
- タスクがコードと一緒に保存されるので、セッションやコンテキスト圧縮をまたいで計画が残る。Linear などのチームの課題管理と双方向に同期する。
- 1.0 になり機能が増えて重くなった。版の違うクライアントは同じ保存先を共有できないので、版を固定し、AGENTS.md に書き込まれる指示を確かめる。

### 75. Chaos Mesh

- クラウドネイティブなシステムに制御された障害を入れるカオスエンジニアリングの道具である。障害の定義を Kubernetes のカスタムリソースで書き、バージョン管理できる。GPU の多い AI インフラの耐障害性の確認にも使える。

### 76. Cube Core

- 指標、次元、結合、アクセス規則をコードで定義するオープンソースのセマンティックレイヤーである。指標を一度定義すれば、BI、組み込み分析、AI のワークフローに同じ定義で出せる。

### 77. Figma Code Connect

- Figma のコンポーネントを、実際のコードのコンポーネントに対応づける。AI やエージェントは、推測ではなく実際のコンポーネントの引数で UI を組み立てられる。
- Figma MCP サーバーと組み合わせるとよい。生成結果の品質はデザインシステム次第で、lint やスナップショットなどのガードレールは引き続き要る。画面全体のレイアウトや状態は人が見る。

### 78. FluxMarkdown

- macOS の Finder のプレビューで Markdown を表示する QuickLook プラグインである。構文の色分け、KaTeX の数式、Mermaid などの図を描ける。エディタを開かずにエージェントの出力した文書を確かめられる。

### 79. Git AI

- AI が書いたコード行を、それを書いたエージェント、モデル、プロンプトに結びつけて記録する Git の拡張である。git notes を使ったオープンな形式で、人と AI のどちらが書いた行かを残す。
- 後から人やエージェントが元の文脈や設計判断を引き出せる。

### 80. Linear

- Trello の手軽さと Jira の計画機能を併せ持つ課題管理である。エージェントがワークスペースのメンバーになり、課題を割り当てられる。Claude Code などはリモート MCP サーバーから課題を読み書きできる。
- チームが計画する仕事は Linear に、エージェントが作業中に作る細かいタスクは Beads に置く。

### 81. mattpocock/skills

- エージェントを使ったソフトウェア開発のためのスキル集である。小さく、変えやすく、組み合わせられるように作られている。grilling もここに含まれる。
- スキル集を丸ごと取り込むことには注意を促しつつ (agent skill cognitive surrender)、このように軽いものは見る価値があるとしている。

### 82. OpenSpec

- どのコーディングエージェントでも使える、軽い仕様駆動開発のフレームワークである。既存のコードに後から仕様を付けられる点が評価されている。
- 変更は永続する正本の仕様に対する差分として扱う。差分を保管する仕組みはあるが、正本の仕様を保守し続ける規律は要る。

### 83. OpenWiki

- コードベースや個人の知識リポジトリについて、原資料からリンク付きの Markdown の wiki を自動で書き、原資料の変化に合わせて更新する CLI である。他のエージェントのコンテキストに使える。
- 文書ごとに最後に生成した時点を記録する。ローカルモデルや、構造化文書の形式である OKF に対応する。人向けに wiki をノードのグラフとして見せる機能もある。

### 84. Pi

- TypeScript で書かれた最小限のオープンソースのエージェントハーネスである。MCP、サブエージェント、計画モード、権限確認を意図的に持たず、拡張やスキルで足す。
- 直接使うより、セキュリティスキャナーやオーケストレーション用ハーネスの土台として広まった。企業向けのコーディングハーネスとしては OpenCode のほうが向く。

### 85. Sourcebot

- 何千ものリポジトリを索引付けする、自前運用のコード検索・理解の基盤である。MCP サーバー経由でエージェントが組織全体のコードを検索できる。

### 86. Timefold Solver

- Java と Kotlin の制約最適化エンジンで、OptaPlanner の後継である。配送経路、勤務表、作業割り当てなどを、学習ではなく制約に基づくヒューリスティック探索で解く。

## Assess

### 87. AgentsView

- 過去の AI コーディングセッションを閲覧、検索、分析 (context profiling) できる。Claude Code、Codex、OpenCode、Pi のセッションを取り込み、キャッシュや費用の効率を示す。
- ローカルで完結する設計で、セキュリティに厳しい組織でも導入しやすい。

### 88. Apple container

- Apple シリコン上で Linux コンテナを動かすオープンソースの道具で、コンテナごとに軽い VM を立てる。Docker Desktop のライセンス要件を避けられる。

### 89. Deepsec

- まずコードベースの構造を調べ、決定的な照合で高リスクのファイルを特定し、そこだけサブエージェントで調べる脆弱性スキャナーである。モデルの注意を絞ることでトークンと費用を抑える。

### 90. DeepSeek Harness (DSH)

- モデルの接続、ツールの登録、セッションログ、エージェントループまですべてをプラグインにした、オープンソースのエージェント実行環境である。プラグインの登録を取り消し可能な効果として扱うので、再読み込みや解体で状態が残らない。
- すべての入出力を追記専用のセッションログに残し、検査、再開、分岐、再生ができる。

### 91. Entire CLI

- コーディングエージェントのセッション (プロンプト、記録、ツール呼び出し、触ったファイル) を Git に記録し、生成したコミットの横に置く。チームで共有して、互いのプロンプトの仕方を学べる。
- 誰がどうプロンプトを書いたかが永久に残るため、抵抗を感じる開発者もいる。信頼の厚いチーム向けで、個人で振り返るだけなら AgentsView がある。

### 92. FreeToken

- 巨大な MoE のオープンウェイトモデルを一般向けのハードウェアで動かす推論エンジンである。使われる専門家だけを GPU に載せ、GPU メモリ、CPU、主記憶を組み合わせる。

### 93. GLM

- Z.ai のモデルファミリーで、ソフトウェア開発で特に強い。GLM-5.3 はコーディング用途で最良級のオープンウェイトモデルである。
- 単純なプロンプトでも考えすぎることがあるので、作業の難しさに応じて推論の強さを設定する。

### 94. Habit Hooks

- Ruff や ESLint などの静的解析の結果を、そのままではなく、対応するコードの臭いと具体的な改善の指針に変換してエージェントに渡す。
- 違反を消すだけの表面的な修正ではなく、設計上の問題に対処させる。決定的なフィードバックセンサーの実装例である。

### 95. Herdr

- 複数のコーディングエージェントのセッションを管理するターミナルマルチプレクサーである。tmux のような操作に加え、作業中、待ち、完了などのエージェントの状態を表示する。GUI を好む人には T3 Code、Orca、Paseo がある。

### 96. Hunk

- コーディングエージェントの変更をレビューするための、ターミナルの差分ビューアーである。エージェントがスキル経由でレビューを操作し、変更した行の横に理由のメモを付けられる。
- 行単位の人のレビューがこの先も主流かは分からないが、今は必要なチームが多い。メモでレビューが速くなるか、読む量が増えるだけかを確かめる。

### 97. nono.sh

- VM や Docker を使わず、OS の機能 (Linux の Landlock、macOS の Seatbelt) でエージェントのプロセスを隔離する軽いサンドボックスである。SSH 鍵などへのアクセスを既定で塞ぐ。
- 設定の手間が少なく、サンドボックス導入の壁を下げる。設定はレジストリで共有できる。

### 98. OpenResearch CLI (orx)

- Claude Code などを、実験を並列に回す研究エージェントにするハーネスである。実験ごとに Git worktree を分け、同じ実行コマンドと固定したコードのスナップショットで再現性を保つ。
- 論文の手法を実装して再現し、自社の文脈でも結果が成り立つかを確かめるのに使える。

### 99. Safe Chain

- npm、pip、uv などのパッケージマネージャーを包み、公開から 48 時間以内の版と、脅威情報で悪意があるとされたパッケージを遮断する。
- まずは各パッケージマネージャーの「最小公開経過時間」の設定を使う。Safe Chain はプロジェクト外の一回限りの実行などを補う。AGPL か商用ライセンスである。

### 100. Swamp

- エージェントに運用作業を直接やらせると毎回やり方が変わり記録も残りにくい。Swamp では、エージェントに TypeScript のモデルと YAML のワークフローとして自動化を書かせ、Git に残す。
- 実行結果はバージョン付きのデータとして残り、認証情報は実行時に保管庫から入る。新しく変化が速いので、低リスクの社内自動化から試す。

### 101. Vale

- Markdown などの文章を、リポジトリに置いた YAML のスタイル規則で検査する文章用の linter である。Google や Microsoft の文書スタイルの規則集がある。
- LLM が下書きした文書が増えたため重要性が増した。生成文らしい言い回しを検出する規則集もある。エージェントのフィードバックセンサーとして使える。
- 語句やパターンの照合なので、推論の弱さや作り話は見抜けない。

### 102. Varlock

- 変数の名前、型、検証規則を書いた `.env.schema` をコミットし、実際の値は実行時に外部の保管庫から入れる。設定の契約と値を分ける。
- 認証が要る通信では、エージェントには代わりの値を渡し、ネットワークの境界で本物に置き換える。エージェントに平文のシークレットを見せない。

### 103. zizmor

- GitHub Actions のワークフローの静的解析ツールで、テンプレートインジェクション、広すぎる権限、可変タグでのアクションの固定、危険なトリガー (`pull_request_target`) を見つける。
- 今年、Trivy のリポジトリで `pull_request_target` が悪用され、アクションのタグが書き換えられた。エージェントもパイプラインを書いたときに実行できる。GitHub Actions 以外は対象外である。
