# Thoughtworks Technology Radar Vol.34: Tools

Thoughtworks Technology Radar Vol.34 (2026 年 4 月) の Tools (道具) 象限の要約である。
Claude Code と Cursor が Adopt に入り、コーディングエージェントを支える道具 (配布、隔離、追跡、仕様、品質の検査) が多く並ぶ。

- 出典: Thoughtworks Technology Radar Volume 34 (PDF)、[thoughtworks.com/radar](https://www.thoughtworks.com/radar)

[TOC]

## Adopt

### 66. Axe-core

- Web サイトなど HTML ベースのアプリケーションのアクセシビリティの問題を見つけるオープンソースの検査道具である。WCAG の A、AA、AAA の各水準への適合を調べる。
- 欧州アクセシビリティ法などでアクセシビリティは必須の品質になりつつある。CI に組み込んで後退を防ぎ、AI やエージェントがコードを書く場面でもフィードバックのループに入れる。

### 67. Claude Code

- 複雑な多段の作業を計画し実行する、Anthropic のエージェント型コーディングツールである。社内外のチームが本番の開発で日常的に使い、能力と使いやすさの基準とみなされているため Adopt に移った。
- コード作成だけでなく、仕様、ストーリー、設定、インフラ、文書、Markdown で書かれた業務手順の実行にも使われる。スキル、サブエージェント、リモート操作、エージェントチームなど、他の道具が追う機能を先に出している。
- 開発者の作業は、手で実装することから、意図、制約、レビューの境界を決めることへ移る。AI が書いたコードへの慢心の危険も増すので、規律ある運用と組み合わせる。

### 68. Cursor

- Claude Code と並び、デリバリーチームが既定で選ぶコーディングエージェントである。計画モード、フック、サブエージェントを備えた総合的なエージェント環境になった。
- IDE の中でエージェントを監督するほうが、計画の確認と修正がしやすいと感じる開発者も多い。個々の手順を確かめたり、計画がずれたときに前の段階へ戻したりできる。Agent Client Protocol により JetBrains の IDE からも使える。

### 69. Kafbat UI

- Apache Kafka のクラスターを監視・管理する、無料のオープンソースの Web UI である。組み込みや追加できるシリアライザーで、暗号化されたメッセージも復号して読める。使い捨てのデバッグ用スクリプトより速く、運用しやすい。

### 70. mise

- 道具と言語のバージョン管理、環境変数の管理、タスク実行の 3 つを、Rust 製の 1 つの道具と宣言的な `mise.toml` にまとめる。asdf の速い代替から、開発環境の既定の入口に育ったため Adopt に移った。
- CI/CD とよく合い、Cosign や GitHub の成果物の証明との連携でサプライチェーンの安全性も高める。言語ごとの既存の道具とも共存でき、一度に移行しなくてよい。

## Trial

### 71. cargo-mutants

- Rust 向けのミューテーションテストの道具である。演算子の入れ替えや既定値を返すなどの小さなバグを自動で入れ、テストが見つけるかを確かめる。ソースを変えずに使える。
- 変異ごとにビルドが要るので時間がかかる。手元では対象モジュールを絞り、全体は CI で非同期に回す。

### 72. Claude Code plugin marketplace

- 独自のコマンド、専用のエージェント、MCP サーバー、スキルを、Git を使って配布する仕組みである。以前は Confluence などからのコピーに頼り、古い指示を使う人が出ていた。
- GitHub などに社内のマーケットプレイスを置き、CLI から手元に同期する。Cursor もチーム向けのプラグインマーケットプレイスに対応している。

### 73. Dev Containers

- `devcontainer.json` で再現できるコンテナの開発環境を定義する標準である。コーディングエージェントを隔離するサンドボックスとして新しい使い道が生まれた。
- ホストのファイル、認証情報、ネットワークから切り離すので、エージェントに広い権限を与えても安全である。起動のたびに作り直すため、永続性が要るなら Sprites などを選ぶ。道具類を宣言的に決めることで、サプライチェーンの安全性も高まる。

### 74. Figma Make

- 生成 AI による画面の試作は広く使われるようになった。Figma Make はデザインシステムの実際の部品とレイヤーを使うので、本番に近い試作ができる。新しい画面の作成、既存の画面の改善、利用者の意見を集める共有の試作に使っている。

### 75. OpenAI Codex

- macOS アプリと CLI を持つ、独立したエージェント型のコーディングツールになった。指示を受けて、計画、実装、修正を最小限の介入で進める。
- 新規開発や繰り返しの多い実装の下書きに効果的だが、筋は通っているが古いライブラリの書き方を提案しがちなので、自動テストと人のレビューが欠かせない。

### 76. Typst

- LaTeX の現代的な後継となる、マークアップ型の組版システムである。構文が単純で、大きな文書もずっと速くコンパイルでき、エラーも分かりやすい。
- 条件分岐やループの記述、JSON や CSV の読み込みができ、文書の自動生成に向く。金融機関向けの明細や報告書を大量に作るのに使った。

## Assess

### 77. Agent Scan

- MCP サーバーやスキルなど手元のエージェントの部品を見つけ、プロンプトインジェクション、ツールの汚染、危険なデータの流れ、埋め込まれた秘密などを指摘するスキャナーである。
- 部品のメタデータを Snyk の API に送る必要があり、誤検知の率も自分の環境で確かめる必要がある。必須のゲートにする前に価値を確かめる。

### 78. Beads

- コーディングエージェントの永続的な記憶として使う、Git ベースの課題管理である。Markdown の計画の代わりに、依存関係や着手可能な作業の検出を持つ構造化されたタスクのグラフを与える。
- 版管理の機能を持つ SQL データベース Dolt の上に作られている。エージェント同士が仕事を割り当て合うような、新しい複数エージェントの協調を可能にする。

### 79. Bloom

- Anthropic による、LLM の迎合や自己保存などの振る舞いを調べる AI 安全性研究向けの道具である。設定をもとに多様な会話を生成して評価する。どの振る舞いが現れるかを調べる Petri と組み合わせる。
- 評価役のモデルにも偏りがあるので、複数の評価役を使う。

### 80. CDK Terrain

- HashiCorp が 2025 年 12 月に廃止した CDK for Terraform (CDKTF) のコミュニティによるフォークである。TypeScript、Python、Go でインフラを定義し、Terraform や OpenTofu で構築する。
- CDKTF の利用者には移行先になるが、放棄された製品のフォークには長期の保守の不安がある。この機会により広く支持された方法へ移るべきかも考える。

### 81. CodeScene

- コードの複雑さと版管理の履歴を組み合わせて技術的負債を見つける、振る舞いに基づくコード分析の道具である。実際の開発活動から「ホットスポット」を示し、リファクタリングの優先順位を付けやすくする。
- CodeHealth という指標で、LLM が安全にリファクタリングできないほど複雑な場所を示す。コーディングエージェントを入れる際のガードレールとして使う。

### 82. ConfIT

- API の結合テストやコンポーネントテストを、コードではなく JSON で宣言的に定義するライブラリである。HTTP クライアントや準備、検証の決まりきったコードを減らせ、AI にも生成しやすい。
- ただし利用者が少なく生態系も小さい。.NET のチームが仕様駆動の API テストを試す場合に検討する。

### 83. Entire CLI

- Git に連携して、AI コーディングエージェントのセッション (記録、プロンプト、ツール呼び出し、触ったファイル、トークン使用量) を、専用のブランチに検索できる形で保存する。Claude Code、Gemini CLI、OpenCode、Cursor などに対応する。
- 本流の履歴を汚さずに監査の記録を残せ、チェックポイントからやり直すこともできる。まだ新しい。

### 84. Git AI

- AI が書いたコード行を、それを書いたエージェント、モデル、プロンプトに結び付けて記録する Git の拡張である。コミットの間のチェックポイントごとに差分を取り、人と AI のどちらが書いたかを残す。
- git notes を使うオープンな形式である。`/ask` スキルで、人もエージェントも元の意図や設計判断を引き出せる。

### 85. Google Antigravity

- Windsurf の技術をもとにした VS Code のフォークで、2025 年 11 月に Gemini 3 と共に公開プレビューになった。Agent Manager が複数のエージェントを並列に動かし、内蔵のブラウザーでエージェントが画面を操作できる。
- 開発者の役割を、1 行ずつ書くことから複数の自律的な作業を指揮することへ変える。正式版の時期が未定で、セキュリティと企業での使用への準備が整っていない。

### 86. Google Mainframe Assessment Tool

- メインフレームのアプリケーションを解析し、決定的なパーサーで呼び出しの流れやデータの依存関係を地図にする。その上で生成 AI が要約、文書化、テストケースの生成、近代化の提案をする。
- 確かな構造の理解を土台に AI を使う、レガシーコード理解の型の例である。

### 87. OpenCode

- 端末中心の使い心地を持つ、代表的なオープンソースのコーディングエージェントになった。ホスト型のモデル、自前の推論先、ローカルモデルのどれでも使え、費用の管理や閉じた環境に向く。
- プラグインと MCP で拡張でき、Oh My OpenCode という、エージェントチームを備えたより作り込まれた構成も人気がある。

### 88. OpenSpec

- 人と AI エージェントが、コードを生成する前に何を作るかで合意するための、軽い仕様の層を加えるオープンソースの仕様駆動開発のフレームワークである。流れは提案 → 適用 → 保管の 3 段階に絞られる。
- 仕様を最初に全部書くのではなく仕様の差分に注目するので、既存のシステムに向く。モデルが強くなればこうした道具が要らなくなる可能性も見続ける。

### 89. PageIndex

- 文書を埋め込みベクトルに分割せず、目次のような階層の索引を作り、LLM がそれを順にたどって必要な部分を取ってくる、ベクトルを使わない RAG の道具である。なぜその部分を選んだかの理由が残る。
- 財務報告書、法律文書、臨床・科学文書のように、意味が構造に強く依存する文書に向く。検索に LLM の推論が入るので遅延と費用が増える。

### 90. Pencil

- IDE やコーディングエージェントと連携するデザインのキャンバスである。双方向のローカル MCP サーバーで、エージェントがキャンバスを読み書きできる。
- デザインを `.pen` という開いた JSON 形式でリポジトリに置き、コードと一緒に版管理できる。専任のデザイナーがいないチームに向く。

### 91. Pi

- TypeScript で書かれた、最小限のオープンソースの端末向けコーディングエージェントである。OpenCode より手を入れやすく、ADK や LangGraph でエージェントを一から作るより適応させやすい。
- まだ初期段階で、主に 1 人の作者が保守している。企業向けの完成した基盤ではなく、エンジニアが使う部品として扱う。

### 92. Qwen 3 TTS

- 商用製品との品質の差を大きく縮めた、オープンソースの音声合成モデルである。多言語に対応し、10〜15 秒ほどの音声から声を複製でき、微調整もできる。本番で使う前に安定性、安全対策、ライセンスを確かめる。

### 93. SGLang

- 前段のプログラミング言語と後段の実行環境を一緒に設計し、LLM の推論の計算量を減らす高性能な提供基盤である。RadixAttention でプロンプト間の KV キャッシュを再利用する。
- 長いシステムプロンプトや共通の少数例を使うエージェントで、vLLM などより大きく速くなることがある。

### 94. ty

- Rust で書かれた、とても速い Python の型検査器と言語サーバーである。uv や ruff と同じ Astral の道具群の一部である。
- エージェントによるコーディングが増える中、速く決定的な型検査は誤りを早く見つけ、単純な誤りのレビューを減らす。

### 95. Warp

- 「AI 機能付きの端末」を超え、Markdown の表示、ファイルツリー、ファイルを開く機能を持つようになった。1 つのペインで Claude Code、別のペインでシェル、さらに別のペインでファイルを見るといった使い方ができる。
- エージェントの大量の出力を、従来の端末よりうまく表示できる。機能の追加が速く、製品が安定するまで Trial には上げない。軽く組み合わせやすい端末なら Ghostty もある。

### 96. WuppieFuzz

- OpenAPI の定義から正しいリクエストを作り、それを変化させ、サーバー側のカバレッジを手がかりに新しい経路に届く入力を優先する、REST API 向けのオープンソースのファザーである。
- 例に基づくテストでは見つからない、未処理の例外、認可の抜け、機密の漏洩などを見つけられる。外部に公開する重要な API を作るチーム向けである。

## Caution

### 97. OpenClaw

- 作者が「超個人的な AI アシスタント」と呼ぶオープンソースのプロジェクトである。自分で運用し、WhatsApp や iMessage などから常に使え、つないだ道具で作業を実行させる。会話や好みを覚え続ける。
- 魅力は大きく、Claude Cowork などの後続も生んだが、カレンダー、メール、ファイルなどへのアクセスを与えるほど便利になり、同時に権限が集中する。toxic flow analysis で警告した形そのものである。
- この危険は OpenClaw に限らず、同じ型の製品すべてに当てはまる。NanoClaw や ZeroClaw は被害の範囲を減らせるが、型そのものの危険は残る。
