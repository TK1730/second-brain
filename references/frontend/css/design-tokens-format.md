# Design Tokens: Design Tokens Format Module 要約

Design Tokens Community Group の「Design Tokens Format Module」（2025.10 版）の要約である。
ツール間でデザイントークンを受け渡すためのファイル形式の技術仕様である。
この文書は Draft Community Group Report であり、W3C 標準ではなく、W3C Standards Track にも載っていない。
原典の状態欄は preview draft で、この版を実装せず、権威ある根拠としても参照しないよう求めている。
外部資料の要約であり、最終的な根拠は原典を参照すること。
要点は「デザイントークンは名前と値の組（JSON）」「`$value` を持つオブジェクトがトークン、持たないものがグループ」「値は別のトークンを参照できる」の 3 つである。

## デザイントークンとは

出典: 2. Introduction / 3. Terminology

デザイントークンは、デザイン上の決定を、プラットフォームに依存しない形で表す手法である。
この仕様は、標準のファイル形式を定めて、ツール間の連携にかかる手間を減らすことを目指している。

- トークン: 人が読める名前に結び付いた情報で、最小限は名前と値の組である（例: `color-text-primary: #000000;`）。
- 型: 値に付ける、あらかじめ決まった分類（color、duration など）である。
- グループ: トークンの任意の集まりである。
  ツールはグループから型や用途を推測すべきでない（SHOULD NOT）。
- エイリアス（参照）: 値が別のトークンへの参照になっているもの。
- 複合トークン: 値が、名前の付いた複数の子の値でできているトークン（影、文字の組みなど）。

## ファイル形式

出典: 4. File format

デザイントークンのファイルは、この仕様の構造に従う JSON ファイルである。
JSON を選んだ理由は、対応する言語が多いこと、広く使われていること、手で編集できることである。

- メディアタイプは `application/design-tokens+json` を使うべき（SHOULD）である。
  `application/json` で配信してもよい（MAY）。
  開けるツールは、両方に対応しなければならない（MUST）。
- 拡張子は `.tokens` または `.tokens.json` を推奨している。

## トークンの名前と値

出典: 5. Design token

`$value` プロパティを持つオブジェクトがトークンである。
親オブジェクトのキーがトークンの名前になり、名前と値は必須である。
例: `"token name": { "$type": "color", "$value": { ... } }` は、名前が `token name` のトークン 1 つを定義する。

- 名前は、RFC 8259 の有効な JSON 文字列でなければならない（MUST）。
- 名前は大文字・小文字を区別する。
  ただし、大文字・小文字だけが違う名前は、変換先で重複するおそれがある。
- この仕様のプロパティは、すべて `$` で始まる。
  そのためトークン名とグループ名は `$` で始めてはならない（MUST NOT）。
- 参照の構文のため、名前に `{`、`}`、`.` を使ってはならない（MUST NOT）。

## 追加のプロパティ

出典: 5.2 Additional properties / 8. Types

必須なのは `$value` だけで、次のプロパティを任意で付けられる。

- `$description`: トークンの目的を説明する平文の文字列。
- `$type`: トークンの型。
  値は、この仕様が定める型の名前（大文字・小文字を区別する）でなければならない（MUST）。
  省略したときは、値が参照なら参照先の型、そうでなければ最も近い親グループの `$type` を受け継ぐ。
  どちらでも決まらないトークンは無効で、ツールは値の中身から型を推測してはならない（MUST NOT）。
  明示した型に値が合わない場合も無効である。
- `$extensions`: ツール固有のデータを入れるオブジェクト。
  キーはベンダー固有にし、衝突を避けるため逆ドメイン表記を推奨している。
  理解できない拡張データは、保存するときも保持しなければならない（MUST）。
- `$deprecated`: 廃止の印。
  `true` は廃止（理由なし）、文字列は廃止とその理由、`false` は廃止ではない（グループの既定を上書きできる）。

## グループ

出典: 6. Groups

`$value` を持たない JSON オブジェクトがグループである。
グループは、子のトークン、入れ子のグループ、`$` で始まるプロパティを含められる。
`$value` と子のトークンやグループを同時に持つオブジェクトは無効で、ツールはエラーにしなければならない（MUST）。

- `$root`: グループの基準となる値を表す、予約されたトークン名。
  参照は `{color.accent.$root}` と書く。グループそのもの（`{color.accent}`）はトークン参照として無効である。
- グループのプロパティは、`$description`、`$type`（配下の既定の型）、`$extends`、`$deprecated`、`$extensions` である。
- `$extends`: 別のグループのトークンとプロパティを受け継ぐ。
  トークンは指せず、循環してはならない（MUST NOT）。
  同じパスはローカルの定義が丸ごと置き換え、違うパスは共存する。
- 空のグループも許される（MAY）。

## エイリアスと参照

出典: 7. Aliases / References

トークンは、明示した値の代わりに、別のトークンの値を参照できる。
この仕様では「エイリアス」と「参照」は同義語で、値の繰り返しをなくし、関連する値の一貫性を保つのに使う。

- 波括弧の構文: `"$value": "{colors.blue}"`。
  完全なトークンだけを指し、常に対象の `$value` に解決される。
- JSON Pointer の構文（対応必須、MUST）: `"$ref": "#/colors/blue/$value/components/0"`。
  RFC 6901 に従い、文書内の任意の場所を指せる。値の中の個別のプロパティの参照は、この構文でだけ書ける。
- 参照は循環してはならない（MUST NOT）。ツールは検出してエラーにしなければならない（MUST）。
- 連鎖（エイリアスが別のエイリアスを指す）も許され、明示した値までたどる。

## 型の一覧

出典: 8. Types

すべてのトークンは、この仕様が定める型のどれかを使わなければならず（MUST）、値はその型の規則と構文に従わなければならない。

| `$type`       | 表すもの                           | 値の形                                                               |
| :------------ | :--------------------------------- | :------------------------------------------------------------------- |
| `color`       | UI の色                            | 別の Color module で定義                                             |
| `dimension`   | 1 次元の距離（位置、幅、半径など） | `{ "value": 数値, "unit": "px" または "rem" }`                       |
| `fontFamily`  | フォント名                         | 文字列、または優先順の文字列の配列                                   |
| `fontWeight`  | フォントの太さ                     | 1 から 1000 の数値、または定義済みの文字列（`bold`、`regular` など） |
| `duration`    | アニメーションにかかる時間         | `{ "value": 数値, "unit": "ms" または "s" }`                         |
| `cubicBezier` | アニメーションの進み方             | 4 つの数値 `[P1x, P1y, P2x, P2y]`（x は 0 から 1 の範囲）            |
| `number`      | 数値（グラデーションの位置など）   | JSON の数値                                                          |

## 複合型

出典: 9. Composite types

複合型は、決まった構造の複数の部分値（サブ値）を持つ型である。
サブ値は、明示した値でも、同じ型を持つ別のトークンへの参照（`{some.other.token}`）でもよい。

| `$type`       | 表すもの           | 主な構造                                                                    |
| :------------ | :----------------- | :-------------------------------------------------------------------------- |
| `strokeStyle` | 線や枠線の様式     | 文字列、またはオブジェクト                                                  |
| `border`      | 枠線               | `color`、`width`、`style`                                                   |
| `transition`  | 状態間の遷移       | `duration`、`delay`、`timingFunction`                                       |
| `shadow`      | 影                 | 影のオブジェクト、またはその配列（`color`、オフセット、ぼかし、広がりなど） |
| `gradient`    | 色のグラデーション | ストップ（`color`、`position`）の配列                                       |
| `typography`  | 文字の組み         | `fontFamily`、`fontSize`、`fontWeight`、`letterSpacing`、`lineHeight`       |

グループと複合トークンは別物である。

- グループは名前付けや整理のための入れ物で、トークンの外にある。
  参照できず、ツールはグループから特別な意味を推測してはならない（MUST NOT）。
- 複合トークンは、それ自体が 1 つのトークンなので、ほかのトークンから参照できる。
  サブ値の名前と型は決まっていて、足したり誤ったりすると無効になる。
