# Vercel: Web Interface Guidelines 要約

Vercel が公開している、Web の画面を作るときの判断を並べたチェックリスト「Web Interface Guidelines」の要約である。
原典は完全なものを目指さない、更新され続ける一覧であり、多くはフレームワークに依存しないが、一部は React と Next.js に固有である。
外部資料の要約であり、最終的な根拠は原典を参照すること。
行数を抑えるため、原典の細かな項目（約 35 件）は省いている。
要点は「キーボードで操作でき、焦点と当たり判定が明確で、動きと読み込みが邪魔をせず、フォームと文言が利用者を迷わせない」ことである。

## 操作（Interactions）

出典: Interactions

- すべての流れをキーボードで操作でき、WAI-ARIA Authoring Patterns に従う。
- 焦点を持てる要素には、見える焦点リングを出す。
  - `:focus` より `:focus-visible` を使い、グループの部品には `:focus-within` を使う。
  - 固定のヘッダー、フッター、バナー、重なる要素が、焦点のある要素を隠さない。
- 焦点の管理（フォーカストラップ、移動、戻し）は WAI-ARIA Patterns に従う。
- 見た目の大きさと当たり判定を合わせる。
  見た目が 24px 未満なら、当たり判定を 24px 以上に広げる。モバイルでは最小 44px とする。
- モバイルの `<input>` の文字サイズは 16px 以上にする（iOS Safari の自動拡大を防ぐため）。
  代わりに viewport の `maximum-scale=1` を設定する方法もある。
- ブラウザの拡大を無効にしない。
- `<input>` と `<textarea>` で貼り付けを禁止しない。
- スピナーやスケルトンには、短い表示の遅延（約 150〜300 ms）と最短の表示時間（約 300〜500 ms）を設け、ちらつきを防ぐ。
  React の `<Suspense>` は自動でこれを行う。
- 状態を URL に持たせ、共有、再読み込み、戻る・進むが効くようにする（例: nuqs）。
- 成功しそうなときは UI をすぐ更新し、サーバーの応答で整合させる。
  失敗したら、エラーを示して元に戻すか、元に戻す手段（Undo）を出す。
- 続きの入力を求めるメニュー項目（「Rename…」など）と、処理中の表示（「Loading…」「Saving…」など）は、末尾を省略記号にする。
- 破壊的な操作は、確認を求めるか、安全な猶予のある Undo を用意する。
- 操作部品に `touch-action: manipulation` を設定し、ダブルタップによる拡大を防ぐ。
- モーダルやドロワーなどでは、意図して `overscroll-behavior: contain` を設定する。
- デスクトップのゴムバンド効果を抑えるには、`@media (pointer: fine)` の中で `<html>` に `overscroll-behavior: none` を設定する。
  - タッチ端末では、ページの既定を保ち、プルして更新を残す。
  - `pointer` は主な入力を表すので、タッチ併用の端末は別に試す。
  - `none` は、スクロールの連鎖とネイティブのスワイプ移動も無効にする。
- 主な入力が 1 つのデスクトップ画面では、自動で焦点を当てる。
  モバイルでは、キーボードの表示でレイアウトがずれるので、ほとんど使わない。
- フィルター、タブ、ページ送り、開閉する領域など、`useState` を使う状態はすべてディープリンクにする。
- ドラッグ中は、テキスト選択を無効にし、`inert` を適用して、選択やホバーが同時に起きないようにする。
- ドラッグ、スワイプ、ピンチ、軌跡を使う操作には、必須でない限り、タップ・クリックとキーボードの代替手段も用意する。
- 遷移には `<a>` や `<Link>` を使い、Cmd/Ctrl+クリック、中クリック、右クリックなどの標準動作を保つ。
  `<button>` や `<div>` で代用しない。
- 非同期の更新（トーストや入力検証）は、控えめな aria-live で通知する。
- キーボードショートカットは、QWERTY 以外の配列にも対応し、環境に合った記号を表示する。

## アニメーション（Animations）

出典: Animations

- `prefers-reduced-motion` を尊重し、動きを減らす版を用意する。
- 実装は CSS を優先し、メインスレッドの JavaScript による動きは避ける。
  - 優先順位は、CSS、Web Animations API、JavaScript ライブラリの順である。
- `transform` と `opacity` を優先し、`width`、`height`、`top`、`left` のように再配置や再描画を起こす性質は避ける。
- 原因と結果を明確にするとき、または意図した楽しさを加えるときだけ動かす。
- イージングは、変わるもの（大きさ、距離、きっかけ）に合わせて選ぶ。
- 動きは、利用者の入力で中断できるようにする。
- 自動再生は、音のない重要でない繰り返しだけにする。
  ほかの内容と並んで 5 秒を超えて自動で動くものには、一時停止、停止、非表示の操作を付ける。
- 動きの起点は、物理的に始まる位置に置く。
- `transition: all` は使わず、動かす性質（通常は `opacity` と `transform`）だけを明示する。
- SVG の変形は `<g>` で包んで適用し、`transform-box: fill-box; transform-origin: center;` を設定する（Safari の起点の不具合を避ける）。

## レイアウト（Layout）

出典: Layout

- ノッチなどは、セーフエリアの変数で考慮する。
- 大きさの決定は、JS での計測より、flex、grid、内在的なレイアウトに任せる。

## 内容（Content）

出典: Content

- 説明は、まずその場に書く。ツールチップは最後の手段にする。
- スケルトンは、最終的な内容と正確に同じ形にして、レイアウトのずれを防ぐ。
- `<title>` は、いまの文脈を正しく表す。
- どの画面にも、次の一手か回復の道を用意する。
- 空、まばら、密、エラーの各状態を設計する。
- 引用符は、直線 `"` ではなく曲線 `“ ”` を使う。
- 数値の比較には `font-variant-numeric: tabular-nums` か等幅フォントを使う。
- 色だけに頼らず、状態を文字のラベルでも示す。
- 三点リーダーは `...` ではなく `…` を使う。
- 利用者が作る内容が、短い、普通、非常に長いのいずれでも、レイアウトが耐える。
- 日付、時刻、数値、区切り、通貨は、利用者のロケールに合わせて整形する。
- 言語は `Accept-Language` と `navigator.languages` で判断し、IP や GPS には頼らない。
- ブランド名、製品名、コードの語、技術的な識別子は、`translate="no"` で自動翻訳から守る。
- アクセシブルな名前（`aria-label`）を正しく付け、飾りは `aria-hidden` で隠し、アクセシビリティツリーで確認する。
- アイコンだけのボタンには、説明的な `aria-label` を付ける。
- `aria-*` より先に、ネイティブの要素（`button`、`a`、`label`、`table`）を使う。
- 見出し `<h1>` から `<h6>` を階層的に使い、「Skip to content」のリンクを置く。
- メディアは、発話や意味のある音に字幕を付け、音だけのものには文字起こしを付け、重要な映像情報は言葉で説明する。
  装飾のメディアは支援技術から隠し、操作部品はキーボードで操作できるようにする。
- 単位、ショートカット、名前を切り離したくないときは、改行しない空白を使う（`10&nbsp;MB`）。

## フォーム（Forms）

出典: Forms

- 入力欄が 1 つだけなら Enter で送信する。部品が多いときは、最後の部品で Enter 送信とする。
- `<textarea>` では、⌘/⌃+Enter で送信し、Enter は改行にする。
- すべての部品に `<label>` を付けるか、ラベルと関連付ける。
- 送信ボタンは送信が始まるまで有効にし、処理中は無効にしてスピナーを出し、冪等性キーを付ける。
- 数値だけを受け付ける欄でも、入力は妨げず、検証の結果を示す。
- 入力が不完全でも送信を許し、検証の結果を示す（送信ボタンを先に無効にしない）。
- チェックボックスとラジオは、ラベルと部品が 1 つの広い当たり判定を共有する。
- エラーは該当する欄の横に出し、送信時は最初のエラーに焦点を移す。
- `autocomplete` と意味のある `name` を設定し、自動入力を助ける。
- メール、コード、ユーザー名などでは、スペルチェックを無効にする。
- 正しい `type` と `inputmode` を使い、キーボードと検証を適切にする。
- プレースホルダーは、空であることを示し、末尾を省略記号にする。
  値は、例や形式にする（例: `+1 (123) 456-7890`）。
- データが失われそうな遷移の前に、警告する。
- パスワード管理ツールと 2 要素認証に対応し、ワンタイムコードの貼り付けを許す。
- 検索など認証でない欄では、パスワード管理ツールを誘発しない。
  予約された名前を避け、`autocomplete="off"` か、OTP 欄なら `autocomplete="one-time-code"` を使う。
- ネイティブの `<select>` には、`background-color` と `color` を明示する（Windows のダークモードのコントラスト不具合を避ける）。

## 性能（Performance）

出典: Performance

- 再描画の回数を最小にして速くする（React DevTools か React Scan を使う）。
- 大きなリストは仮想化する（virtua か `content-visibility: auto`）。
- ファーストビューの画像だけを先読みし、ほかは遅延読み込みにする。
- 画像には明示的な寸法を指定し、場所を確保して、累積レイアウトシフトを防ぐ。
- 資産や CDN のドメインには、`<link rel="preconnect">` を使う（必要なら crossorigin も）。
- 重要な文字のために、フォントを先読みする。
- 重い処理はメインスレッドで行わず、Web Worker に移す。
- 繰り返しの動きには、アニメーション GIF より `<video autoplay muted loop playsinline>` を使い、静止画の代替を用意し、`prefers-reduced-motion` を尊重する。
- Safari では、短く重要でない繰り返しに、`<picture>` へ H.264 MP4 の source を加える方法がある。
  - この source は `prefers-reduced-motion` で制御する。
  - 再生の操作が要る場合や、動きが重要な情報を伝える場合は、`<video>` を使う。

## デザイン（Design）

出典: Design

- 影は、環境光と直接光を模して、2 層以上重ねる。
- 境界線と影を組み合わせ、半透明の境界線で縁をはっきりさせる。
- 入れ子の角丸は、子の半径を親以下にし、曲線が同心になるようにする。
- 無彩色でない背景では、境界線、影、文字を同じ色相へ寄せる。
- コントラストの判断は、WCAG 2 より、知覚に近い APCA を優先する。
- `:hover`、`:active`、`:focus` は、通常の状態よりコントラストを上げる。
- `<meta name="theme-color">` で、ブラウザの色を背景に合わせる。
- ダークテーマでは、`<html>` に `color-scheme: dark` を設定し、スクロールバーなどの UI のコントラストを保つ。

## Vercel 固有の文章表現（Copywriting）

出典: Vercel-specific > Copywriting

この節は、Vercel のブランドと製品の選択であり、普遍の指針ではないと原典が断っている。

- 能動態で書く（「The CLI will be installed」ではなく「Install the CLI」）。
- 見出しとボタンは Title Case（Chicago 式）にする。マーケティングのページは文頭だけ大文字にする。
- 明確で簡潔に、できるだけ少ない語で書く。
- `and` より `&` を使う。
- 行動を促す言い方にする（「You will need the CLI…」ではなく「Install the CLI…」）。
- 二人称で書き、一人称は避ける。
- 個数は数字で書く（「8 deployments」）。
- 数値と単位は空白で区切り（`10 MB`）、改行しない空白を使う。
- 既定では前向きな言い方にし、エラーでも励まし、解決を促す表現にする。
- エラーメッセージは、何が悪いかだけでなく、直し方を示す。
- 曖昧さを避け、ラベルは明確で具体的にする（「Continue」ではなく「Save API Key」）。

## エージェントとの連携（Integrate with Agents）

出典: Integrate with Agents

- UI コードの点検には、`web-design-guidelines` スキルを導入する。
- プロジェクトに AGENTS.md を置くと、生成の最中にエージェントがこの指針を適用する。
